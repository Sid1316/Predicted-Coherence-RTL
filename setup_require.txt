RISC-V Core (Predicted-Coherence-RTL) - Setup Requirements
==========================================================

Platform: native Windows 10/11 (no WSL). Commands run in Git Bash.
Versions below are the ones installed and verified on the development
machine (2026-11-25). Newer versions will probably work; check with
"make check-env" after any change.

Quick check once everything is installed (in a NEW Git Bash window):

    make check-env

3. PATH (user PATH, not system)
-------------------------------

Add these two folders to the user PATH
(Settings > System > About > Advanced system settings > Environment Variables):

    %LOCALAPPDATA%\Programs\xpack-riscv-none-elf-gcc-15.2.0-1\bin
    C:\msys64\ucrt64\bin

Do NOT add C:\msys64\usr\bin: it clashes with Git Bash's own tools.
winget adds make to PATH by itself (%LOCALAPPDATA%\Microsoft\WinGet\Links).
Open a new Git Bash window after changing PATH.


4. PYTHON VIRTUAL ENVIRONMENT
-----------------------------

In Git Bash, in the repository root:

    py -m venv .venv
    source .venv/Scripts/activate
    pip install cocotb

RISCOF workaround (Python 3.14): riscv-config pins PyYAML==5.2, which has no
build for Python 3.14 and would need Microsoft C++ Build Tools. Install
RISCOF without its pins, then its dependencies with the current PyYAML:

    pip install --no-deps riscof riscv-config riscv-isac
    pip install "GitPython==3.1.17" click Jinja2 pytz Cerberus ruamel.yaml pyyaml \
        "pyelftools==0.26" colorlog pytablewriter

"pip check" then reports "riscv-config requires pyyaml==5.2"; this is expected.
The Makefile and scripts/check_env.sh use .venv automatically; activating it
is only needed for running pip or python by hand.

7. GIT AND GITHUB (SSH)
-----------------------

  git config --global user.name  "<your name>"
  git config --global user.email "<your email>"

  SSH key:      ssh-keygen -t ed25519 -C "<your email>"
                (creates ~/.ssh/id_ed25519 and id_ed25519.pub; use a passphrase)
                Add id_ed25519.pub on GitHub: Settings > SSH and GPG keys > New SSH key
  known_hosts:  GitHub host keys (from https://api.github.com/meta)
  ~/.ssh/config:
                Host github.com
                  HostName github.com
                  User git
                  IdentityFile ~/.ssh/id_ed25519
                  IdentitiesOnly yes
                  AddKeysToAgent yes
  ~/.bashrc:    starts one ssh-agent per login in Git Bash and loads the key
                (GitHub's "Auto-launching ssh-agent on Git for Windows" snippet)
  Test:         ssh -T git@github.com
  Remote:       origin = git@github.com:Sid1316/Predicted-Coherence-RTL.git

  Pushing from a PowerShell window: Git's own ssh can't ask for the passphrase
  there, so use Windows' ssh:
    git -c core.sshCommand=C:/Windows/System32/OpenSSH/ssh.exe push


8. KNOWN WINDOWS QUIRKS
-----------------------

  - Verilator: MSYS2's "verilator" command is a Perl script that fails under
    Git Bash's Perl (missing Pod::Usage). The Makefile and check_env.sh call
    the binary directly instead:
      VERILATOR_ROOT=C:/msys64/ucrt64/share/verilator C:/msys64/ucrt64/bin/verilator_bin.exe
  - Python: "python3" and sometimes "python" are Microsoft Store placeholders.
    Use "py" or the .venv interpreter; the scripts detect the real one.
  - Line endings: .gitattributes forces LF for every file, so scripts and the
    Makefile keep working when edited on Windows.
  - Paths with short names (e.g. BAJORI~1) confuse Verilator; use full paths.
